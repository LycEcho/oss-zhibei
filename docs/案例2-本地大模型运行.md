## 这个类型页成稿

### 是什么

「本地大模型运行」指：不连外部服务、在自己电脑或自己服务器上跑开源大模型的工具。好处是数据不出门、没有按量付费；代价是效果受限于你的硬件，电脑越好跑的模型越好。【事实·定位综述】

这个类型里其实住着三种完全不同的角色：给普通人双击就用的桌面软件、给开发者接进自己程序的服务、以及给公司机房扛并发的推理服务器。选错形态是新手最常见的浪费——装了个机房级工具结果只在自己笔记本上聊天。【事实·见形态分段】

### 适合谁 / 不适合谁

适合：数据敏感不想出网的（本地文档问答、内网场景）、想给自己的应用接便宜模型服务的开发者、想折腾学习的人。
不适合：预期「本地免费=ChatGPT 质量」的人——同一句话，本地能跑的模型和云端旗舰模型的差距是肉眼可见的【待确认·需补一个具体对比示例才算锐利】；企业多人共用的需求属于「推理服务器 + API 网关」组合，不是装个桌面软件能解决的【事实·见相关类型】。

### 选型维度表（选这类工具看这五条）

| 维度 | 说明 |
|---|---|
| 硬件门槛 | 无 GPU 普通笔记本 → 消费级显卡 → 机房级 GPU，工具的适配范围差别巨大 |
| 使用形态 | 双击界面聊 / 给程序供 API / 高并发服务——对应下面三个形态段 |
| 模型获取 | 内置模型市场一键下，还是自己去 HuggingFace 找 GGUF 文件 |
| OpenAI 兼容 API | 决定能不能把现有工具（写作助手、代码插件）直接指到本地模型 |
| 后端与量化支持 | 决定你的硬件（Apple 芯片 / N 卡 / A 卡 / CPU）能不能跑、跑多快 |

### 形态分段短名单

#### 段一 · 个人桌面，双击就用

**默认选谁：Jan**（开源协议 Apache 2.0，README 自述口径；GitHub API 识别为「Other」，两处不一致，**协议待核**后此推荐才可定稿【待确认+事实·Jan 协议不一致】）。
理由：桌面 App 开箱即用，从 HuggingFace 拉模型直接聊，还带本地 API 服务器（localhost:1337，OpenAI 兼容）和 MCP 扩展，是从「纯聊天」走向「接工具」最顺的路径【事实·README】。

**什么情况换：**
- 只要最好的图形体验、不在乎闭源 → **LM Studio**（闭源对照项，不进短名单但必须知道它：个人使用长期免费，2026 年起公司使用也免费了【事实·官方博客】；模型发现和下载体验是全场最好的【待确认·界面体验评价需人核】）
- 主要玩角色扮演/故事，要单文件零安装 → **KoboldCpp**（单可执行文件，内嵌浏览器 UI，还带文生图语音【事实·README】）
- 喜欢自己换底层引擎、调参折腾 → **text-generation-webui**（一个界面下可热切换 llama.cpp/ExLlamaV3 等多后端，还能训 LoRA【事实·README】）

**不适合谁**：想在服务器上给全组人用的——这是桌面软件，别硬上。

**停更警示区**：**GPT4All**——网上教程最多的老牌工具，但截至 2026-10-20 已 **17 个月无任何代码提交**（未标归档）【事实·GitHub API push 2025-05-27】。教程还能跑，但别为它做长期选型。

#### 段二 · 开发者：给程序供模型的本地服务

**默认选谁：Ollama**。
理由：一条命令跑起来，官方模型库 `ollama run <模型>` 即用，本机 REST API + Python/JS SDK 齐全，提供 OpenAI 兼容 API（注意：是**子集**，`tool_choice`、`logit_bias`、`n` 等字段不支持——接现有工具链前先查兼容表【事实·docs.ollama.com/openai】）。18.4 万 star、2026-10-20 当日仍有提交【事实·GitHub API】。

**什么情况换：**
- 要极致控制、量化粒度、冷门硬件后端 → 直接用 **llama.cpp**（整个类型的地基：Ollama、Jan、KoboldCpp、LM Studio 底层都是它【事实·各 README】；用 Ollama 其实就已经在用它，直接上 llama.cpp 是要自己造轮子，换来的是每一步都可控【事实+待确认·后半句是定位判断】）
- 要把模型打包成单文件发给别人（离线分发、附件大小受限的场景）→ **llamafile**（llama.cpp+模型合为单个可执行文件；注意 Windows 单文件上限 4GB【事实·README】）
- 要 OpenAI 接口的「无缝替身」+ 多模态 + 多用户隔离 → **LocalAI**（drop-in 兼容 OpenAI/Anthropic/ElevenLabs 接口，带 API key 鉴权、配额、RBAC【事实·README】——严格说它已经一脚跨进「自托管推理网关」类型了【待确认·类型边界】）

#### 段三 · 生产推理服务器（机房 GPU、多用户并发）

**默认选谁：vLLM**。
理由：为「一张/一排 GPU 伺候很多人」设计——PagedAttention 显存管理、continuous batching，自称吞吐 SOTA 且是同类里被引用最多的基线【事实·README，"State-of-the-art serving throughput" 为官方自称，需在复盘标注】；OpenAI 兼容之外还支持 Anthropic Messages API 和 gRPC【事实·README】。

**什么情况换：** Agent 型负载（超长上下文、反复调用、强化学习采样）→ **SGLang**，官方定位明确主攻 agentic workloads 和 RL rollout【事实·README】。两者的 OpenAI 兼容性：vLLM 有据可查，SGLang 本次**未验证到官方文档明说**，采用前需实测【待确认·数据缺口，已如实标注】。

**不适合谁**：没有独立 GPU 服务器的小团队——vLLM/SGLang 的优势建立在机房硬件上，笔记本上跑它们是纯受罪。

### 常见误区

1. **「Ollama 和 llama.cpp 二选一」**——不是竞争关系，Ollama 底层就是 llama.cpp，是包装关系【事实·README】。
2. **「OpenAI 兼容 = 完全兼容」**——Ollama 明确只支持子集【事实·官方文档】，工具链迁移时字段级兼容问题最常见。
3. **拿 star 论英雄**——GPT4All 7.7 万 star 依然停更【事实·GitHub API】；本类型真正的质量信号是发版节奏和 issue 响应。
4. **以为本地模型能白嫖旗舰质量**——本地跑的是缩小版模型，硬件决定上限【待确认·需补具体规模对比】。

### 相关类型

- **API token 网关**：本地模型多了之后，和云模型统一管路由、额度，是网关的活（边界：LocalAI 已经跨在两个类型中间【待确认·边界归属】）
- **AI 编程助手本地接入**：Ollama 已支持直连 Claude Code/Copilot CLI 等编码工具（`ollama launch`）【事实·README】

## 规范执行标注（复盘素材）

1. **形态分段经受住了考验**：三个形态段（桌面/开发者服务/生产服务器）每段都写出了「默认选谁+什么情况换」，没有出现「正确的废话」——初步验证规范 §2.2 可跨类型复用【待案例 1 交叉验证】。
2. **「协议一致性检查」是新增筛选项的候选**：Jan 的 GitHub API 识别与 README 自述不一致——规范 1.1 的「真开源」门槛需要补一条「协议以 LICENSE 文件为准，双口径不一致时标待核」。
3. **数据缺口处理流程生效**：SGLang 的 OpenAI 兼容性、text-generation-webui 的活跃度，均按规范标「待确认」而非编造——事实包的「未获取」标记被完整传递到了成稿。
4. **官方自称与事实的边界**：vLLM「SOTA 吞吐」是官方自称，成稿里保留但标注了「官方自称」——规范需要明确：**性能断言引用官方原文时必须带「自称」标注，除非有第三方 benchmark**。
5. **闭源对照项机制**运作正常：LM Studio 进了页面但明标闭源、不进短名单——「绕不开的非开源项」以对照身份出现，符合规范 1.1 #1。
6. **停更警示区**（GPT4All）成为页面价值点：搜教程来的人最需要的正是「这东西已经死了」的提醒——负面空间建立信任的假设在案例中得到支撑。
