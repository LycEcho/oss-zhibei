### 类型裁决（本漏斗的核心产出）

**裁决 1：做「AI 逆向工程」类型页**（见下节草稿）
理由：双圈交叉最强（rea 双圈之王 + ghidra 双圈连带）；类型完整自洽（agent 自动逆向 + 经典框架底座）；**它是纯雷达产物**——不在任何预设清单里，完全从舆论场长出，正是本次实测要证明的事。

**裁决 2：Agent 配套基建 14 个项目 → 新星观察区，不做类型页**
名单：ruflo、endo、pi-cowboy、keel、agentfork、onememory、plimsoll、MIKE、costura、kompressor、taco、iFixAi、rugsnare、whatsapp-mcp。
理由：全部是 Show HN 当周发布或创建不足半年的项目，样本未分化——**每个细分（记忆/沙箱/计费/编排）只有 1-2 个成员，写不出「默认选谁」**。按规范 0.5：入池留痕、跟踪、够资历再转正。
（此裁决本身是漏斗能力的一部分：发现 ≠ 立刻做页，知道「还不到时候」同样重要。）

**裁决 3：AnyPS5 / 游戏移植 → 相邻独立类型（暂不做）**
逆向的成果被用于移植老游戏，但「游戏移植」是另一个选型场景（关注可玩性/性能/需自备镜像），与「理解程序」不是一次决定。留待雷达继续观察该类型是否成型。

## 二、类型页草稿：AI 逆向工程

### 是什么

「AI 逆向工程」指：把 Ghidra、IDA 这类专业逆向工具接入 AI agent，让 agent 自动分析二进制、还原程序内部逻辑——过去需要逆向工程师几天的工作，现在可以用自然语言驱动工具完成。2026 年 10 月，rea 把这个方向带成现象级话题，中英文社区同时爆发（中文圈称之为「AI 逆向」「大开源时代」）【事实·双圈雷达】。

### 适合谁 / 不适合谁

适合：安全研究员、想搞明白自己设备私有协议的硬件玩家、想深入理解程序内部原理的学习者。
不适合：想「破解商业软件白嫖授权」的——那是绕过技术措施，与「理解程序」是两回事，且明确违法；本页不提供任何破解指引【合规位】。

### 选型维度

| 维度 | 说明 |
|---|---|
| 自动化程度 | agent 全流程自动分析 vs 经典框架人工分析 |
| 底层引擎 | 挂在 Ghidra/IDA 上，还是直接啃二进制 |
| 结果可信度 | 反编译产物永远需要专业知识复核，AI 产物也不例外【待确认·判断句】 |
| 法律边界 | 逆向目的与对象决定合法性（见合规位） |

### 形态分段短名单

#### 段一 · Agent 自动逆向（新形态）

**默认选谁：rea**。
理由：该形态当前唯一的现象级项目——338.4k star（GitHub 历史星榜前 30）、MIT 协议、3,789 commits，从应用行为一路分析到原生二进制【事实·项目页】。中文圈报道它带火了整个「AI 逆向」话题【事实·掘金/网易】。
**使用前必知**：685 个 open issues / 592 个 open PR【事实·项目页】——爆火带来的维护压力是真实的，你提交的 issue 很可能没人理，关键工作流要有备选方案【待确认·判断句，需人核】。

#### 段二 · 经典逆向框架（AI 时代的底座）

**默认选谁：ghidra**。
理由：NSA 出品、Apache-2.0、91.7k star、18,816 commits 的成熟框架，是 rea 这类 agent 工具的底层集成对象【事实·项目页】。要人工精修分析结果、或给自研 agent 找可靠底座，仍是它。
**注意**：它是「因 AI 逆向浪潮连带翻红」——本周 +7.5k star 但项目本身节奏未变【事实·SegmentFault/Trending】，别把翻红误读为项目大更新【待确认·判断句】。

#### 相邻边界

AnyPS5 等游戏移植项目用逆向成果做「让老游戏跑起来」，属于另一类型「游戏移植」——关心的是可玩性，不是理解程序本身。两者共用技能，但不是一次选型决策【事实·裁决 3】。

### 常见误区

1. **「rea 是破解工具」**——不是。它做的是「理解程序」，拿理解成果绕过授权是另一件事且违法【合规位】。
2. **「AI 逆向 = 一句话完美还原」**——反编译产物永远需要专业复核，媒体话术（「一句话拆软件」）和实际产出有距离【待确认·需补实例】。
3. **「star 多 = 可靠」**——rea 一周 +20 万星的同时积压了 685 个未处理 issue；对爆火项目，issue 响应比 star 更能说明可用性【事实·项目页】。

### 合规位（中国法律语境，本类型必备）

为学习、研究目的逆向自己合法获得的软件，一般可行；但绕过技术措施（破解授权）、分发破解产物、将逆向成果用于侵权，有明确法律风险（著作权法、计算机软件保护条例）。本页只覆盖「理解与研究」，不收录、不引导任何破解用途。

## 三、漏斗效果复盘（vs 上一轮发现方式）

| 维度 | 上一轮（种子清单 + 关键词扩散） | 本轮（四层漏斗） |
|---|---|---|
| 发现源头 | 我脑内的清单 + 搜索引擎老文章 | 双圈舆论场（Trending/HN/V2EX/掘金…） |
| 僵尸项目混入率 | 2/11（GPT4All 停更 17 月、one-api 停更 9 月） | **0**（全部项目带两周内热度证据） |
| 新类型来源 | 预设（网关、本地模型都是熟悉领域） | **从热度自己长出**（「AI 逆向」不在任何预设里） |
| 头部项目新鲜度 | one-api（停更中）当默认推荐候选 | rea（当月现象级）当默认推荐候选 |
| 新暴露的风险 | 起点滞后、漏掉新星 | **太新没分化**（agent 基建 14 项目全进观察区）——由新星观察区机制接管 |
| 数据矛盾 | 无 | rea 星数两说（22.3 万 vs 33.8 万）→ 核实为时间点差异，双源皆真 |

**结论**：用户提出的「从新闻/讨论拿知名项目 → 提关键词 → GitHub 搜索」思路 + 加固（发现/验证分离、双圈交叉、验证闸门）= 可运转的发现引擎。上一轮的「僵尸率 2/11」降到 0，且类型能从舆论场自己长出来。

**本轮新沉淀的规则（已写回规范 v0.4）**：
1. source-available 协议（ELv2 等）的处理：不是 OSI 开源，按「受限协议」标注，能否进短名单由人裁决
2. 爆火项目的健康信号：open issues/PR 积压量必须与 star 一起报告
3. 媒体快照数据的时效标注：中文媒体的星数是快照（10-15），引用时注明时点，与实抓数据并存
